## 判定基準

スクリプトの出力は **「手掛かりの有無」であって「パースの成否」ではない。** ページ構造を一度も見ずに書いているため、セレクタを断定していない。

`OK` が出たら保存済みHTMLを開いて、**その項目が使える形で存在するか**を目視で確認する。`NG` が出たら、キーワードが外れているだけかもしれないので同様にHTMLを見る。`--` は導出項目（テキスト照合の対象外）で、頭数がこれにあたる。

### 照合条件を締めた経緯（2026-08-16）

初版の照合は `keywords` と `regex` の **OR** で、条件が緩すぎた。

| 項目 | 初版の条件 | 問題 |
|---|---|---|
| レース番号 | キーワードに `"R"` | 大文字Rはどのページにも出る。**常に OK になる** |
| コーナー通過順 | `\d+-\d+-\d+` | `2024-01-01` のような日付に一致する |
| 単勝オッズ | `\d+\.\d` | インラインJSの小数に一致する |
| 頭数 | `\d{1,2}\s*頭` | `<head>` の meta description の「50万頭」を拾っていた |

**偽 OK が最悪の失敗モードである。** 取りこぼしは保存HTMLを見れば直せるが、偽 OK は誰も見直さない。しかも `D-023` はこの出力を根拠に記録されている。

現在は以下に変えてある。

- `keywords` と `regex` の **AND** 判定にする
- `<script>` `<style>` `<head>` とコメントを判定対象から外す
- 未検出項目の集計を、ページ単位の欠落の**和集合から積集合へ**変える（`archive` にしかない項目が `shutuba` で欠けているだけで「取得不可」と報告されていた）
- 頭数は本文に印字されないため、テキスト照合の対象から外し導出項目とする

**締めた条件で保存済み18ページを再判定した結果、`D-023` の結論は変わらない。** どのページでも見つからなかった項目は0件で、`archive` は全項目が `OK`（`status` は該当馬のいるレースのみ）。`shutuba` / `result` の欠落は `D-037` がページ選択で解決済みの内容と一致する。

## 取れなかった場合に見直すもの

**実測ラップが取れないケースが最も重い。** ここが崩れたら、仕様書を書く前に `D-007` の再検討から入ること。
