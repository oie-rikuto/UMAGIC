# UMAGIC ドキュメント

JRA平地G1に限定した競馬予想モデルの設計ドキュメント群。

## ドキュメントの役割分担

このプロジェクトでは **「なぜそうするか」と「何を作るか」を意図的に分離** している。
設計の根拠を仕様書に混ぜると、仕様変更のたびに根拠が失われ、
逆に根拠を残したまま仕様を書くと読み手が実装すべきものを見失うため。

| ドキュメント | 役割 | 誰が読むか |
|---|---|---|
| [`requirements.md`](./requirements.md) | 満たすべき要件（`R-xxx`） | 完了判定をする人 |
| [`decisions.md`](./decisions.md) | 確定した設計判断とその根拠（ADRログ） | 設計変更を検討する人 |
| [`domain-knowledge.md`](./domain-knowledge.md) | プロの予想プロセスの形式化・特徴量カタログ | 特徴量を実装する人 |
| [`architecture.md`](./architecture.md) | システム構成・スキーマ・Phase計画・評価設計 | 全体像を掴む人 |
| [`open-questions.md`](./open-questions.md) | 未決事項と、決めるために必要な情報 | 次に判断する人 |
| [`spec/`](./spec/) | **実装仕様書（今後追加）** | 実装する人 |
| [`tasks.md`](./tasks.md) | 実作業と完了条件（`P-0`〜`P-3`） | 手を動かす人 |

`design.md` は作らない（`D-019`）。設計は `architecture.md`（全体）と `spec/`（モジュール単位）が担う。

## ID体系

ドキュメント間の相互参照のため、以下のIDを使う。
仕様書を書く際は、これらのIDを参照して「どの決定・どの特徴量の実装仕様か」を明示する。

| プレフィックス | 対象 | 定義場所 |
|---|---|---|
| `D-xxx` | 決定事項（Decision） | `decisions.md` |
| `F-xxx` | 特徴量（Feature） | `domain-knowledge.md` |
| `Q-xxx` | 未決事項（Open Question） | `open-questions.md` |
| `P-x` | 開発フェーズ（Phase） | `architecture.md` |
| `R-xxx` | 要件（Requirement） | `requirements.md` |

`tasks.md` のタスクにはIDを振らない（`D-019`）。

IDは**一度振ったら再利用しない**。決定が覆った場合は元のIDを `Superseded by D-xxx` として残し、新しいIDを振る。

## 仕様書を書くときの手順

1. `docs/spec/` に `NNN-<名前>.md` を追加する（[テンプレート](./spec/README.md)を使う）
2. 冒頭で関連する `D-xxx` / `F-xxx` を参照する
3. 仕様の過程で新たな設計判断が発生したら、`decisions.md` に `D-xxx` を追加してから仕様書側で参照する
   （仕様書の中に根拠を書き込まない）
4. 未決事項が出たら `open-questions.md` に `Q-xxx` を追加する

### `P-4` に進めない理由（`D-103`）

`R-023` 未達の要因を実データで診断した結果（2026-08-25）、**現在のモデルは市場確率に対する上乗せ情報を持たない**ことが分かった。市場確率とモデル確率を対数線形ブレンドして重みを探索すると、23,224レースという十分な検出力で最良重みが `w_model = 0.00` になる。この状態で期待値計算に進めば控除率20%ぶんそのまま負ける。

診断で分かったことは他に4点ある。ギャップの正体は校正ではなく識別力（最適温度で縮むのはギャップの1.6%のみ）。確率の目盛りは壊れていない（信頼性曲線の実測/予測が0.87〜1.07）。学習不足でもない（`best_iteration` は上限200に対して64〜65）。そして**能力の絶対値（走破時計ベース）に相当する特徴量が1本も無い**（→下記 `F-301`/`F-302`）。

### `F-301`/`F-302`（馬場差推定）は実装済みだが既定で無効（`D-104`〜`D-112`）

`Q-025` は解決済み（実装方法は自前の交互反復、`D-104`）。しかし実装して7fold walk-forwardで測定したところ、**`all` 母集団を7fold全て（+0.048〜+0.087の狭い幅）で一貫して悪化させた**。実装過程で `build_features()` の既存バグ（`D-109`、出走取消・競走除外が基底集合に混入し `_rank` 列が1.0を超える。`F-301`/`F-302`に限らず既存21列に影響）も発見・修正したが、修正後の汚染されていない基準でも `F-302` は悪化させた（`D-110`）。

原因究明として `Q-042`（レース効果へのメンバーレベル混入）を検証した。`race_class` が `G1`〜`G3`・`L`・無格付を `'オープン'` 1水準に丸めていることを確認し、`grade` を固定効果に追加した（`D-111`）。7fold walk-forwardで再測定すると **G1側の悪化幅は半減した**（+0.0484→+0.0229）が、**`all`側はほぼ無風**（+0.0702→+0.0697、`D-112`）。`Q-042`はG1側の副次的要因として部分的に実証されたが、`all`が一貫して悪化する主要因ではないと確定した。

`all`側は追加で分解診断も行った（`D-114`）。`F-302`の生値（relativize前）を含む構成は一貫して悪く、除いた構成は一貫して良かった——生値の無制限な尺度（縮約が弱い馬で効果量が二桁に達しうる）が主犯の一つ。しかし relativize 後（`z`のみ・`rank`のみ）でも全除去には届かず、**relativize後もF-302の中身自体がノイズとして働いている**ことが分かった。単純な後処理では埋まらず、`F-301`の推定方法自体（縮約の頑健化等）の見直しが要る、より大きな課題として残った。

`Stage2FoldRunner.include_track_variant` の既定値は `False` のまま。フルの7fold再検証は、見つかったどの候補も現状の既定を上回らなかったため実施していない。

`Q-039`（生IDのカテゴリ正則化）は解決済み。`cat_smooth=200`・`cat_l2=200`を`Stage2FoldRunner`の既定にし、7fold walk-forwardで確認した——`all`が7fold全て（−0.028〜−0.039の狭い幅）・G1（135レース集計）が−0.0270、いずれも改善した（`D-113`）。このセッションで唯一、`R-023`を実際に前進させた変更である。

### 次に手を付けるもの

**`R-023` の本丸（`D-103`）が未着手のまま残っている。** モデルが市場確率に対する上乗せ情報を持たない（対数線形ブレンドの最良重み `w_model=0.00`、23,224レース）という診断への答えがまだ無い。以下はいずれも本丸ではない後片付けである。

1. `min_data_in_leaf=1` の根拠を確定するか既定（20）に戻す（軽微。性能には効いていないことは実測済み）
2. `Q-040` の残り（`F-102` が race-level 特徴量であるためlambdarankのレース内順位に寄与しない、という構造的制約への対処。`D-115`）

### `F-103` の縮約問題は決着した（`D-116` 〜 `D-118`）

`Q-044` を解決した。`F-103` の `β` は `F-302` と**同型の未ロバスト化問題**を抱えていることを実証した（`D-116`）——`β` の std は過去走2走の馬で131.5・21走以上で3.03（43倍差）、`k=5` の縮約は `n=2` で `β` の29%を残すため無力、fold 0 行列の `f103` 最小値 `-1192.11` は過去2走の `p_i` がほぼ同値だった1頭に特定できた。

しかし対処候補5つ（`MIN_VAR_X` 引き上げ・`n_valid_pairs` 下限・`mu_global` 中央値化・併用・単純除去）をG1 OOFで3 fold 比較したところ、**向きが3 fold 揃う候補は1つも無かった**（`D-118`）。**丸ごと除去しても base と区別がつかない**ことから、`F-103` は有害なのではなく**不活性**と判明した——`D-113` の `cat_smooth`/`cat_l2` を含む現在の設定下で LightGBM が実質的に無視できている。

`Q-042`（`F-301`/`F-302`）とは同一の設計課題（精度を無視した標本数だけの縮約）だが、**`F-103` 単体では共通基盤への作り直しを正当化できない**ことが分かった。`F-301`/`F-302` 側で効果が実証されてから展開する順序にする。

`F-302`が`all`母集団を悪化させる要因は`D-114`で分解診断まで完了している。生値の無制限な尺度が主犯の一つと確認したが、relativize後も残る有害性は`F-301`の推定方法自体の再設計が要ることが分かったため、次善の手としては着手しない（保留）。

### 未決のうち優先度が高いもの

`Q-017`（Plackett-Luce の Harville bias）・`Q-018`（複勝・ワイドの過去オッズ）・`Q-019`（発走15分前の締切）。`Q-042`（`F-302`が`all`を悪化させる要因）は分解診断まで完了し優先度を下げた——`F-301`の推定方法自体の再設計が要る大きな課題であり、次善の手として着手するものではない。`Q-017` と `Q-018` は `P-4` の前提であり、`P-4` 自体が上記の理由で止まっている。
