プロの予想プロセスを分解し、アルゴリズムに落とし込むための知識ベース。
仕様書からは `F-xxx` で参照する。

## 1. プロの予想プロセスの構造

流派（血統派・指数派・展開派・調教派）は表面上バラバラに見えるが、**思考の骨格はほぼ共通**である。

```
1. レース質の想定        「どんなレースになるか」を先に決める
2. 求められる適性の特定   その質を勝つには何が要るか
3. 各馬の適性照合        誰がそれを持っているか
4. 状態・人的要因で補正
5. オッズと照合して妙味判断
```

**素人は 1〜2 を飛ばして、いきなり 3 の各馬の能力比較を始める。プロはレースを先に、馬を後に見る。**

そして機械学習モデルの大半も素人と同じ誤りを犯している。馬ごとに独立してスコアを出し最後に並べる構造だからである。この観察が `D-007` の2段階アーキテクチャの根拠になっている。

## 2. 市場を超えられる領域はどこか

`D-002` の両建て方針では、市場確率を超えることがすべての基準になる。
**市場確率は「わかりやすい情報」を完全に織り込んでいる。** 前走着順・人気・騎手・過去実績を特徴量にしても、それらは既にオッズそのものであり、原理的に超えられない。

勝てるとすれば **集計が面倒で人間が定量化を諦めている情報** だけである。

| 優先度 | 領域 | 特徴量群 | 理由 |
|---|---|---|---|
| 1 | 当日馬場バイアス | `F-5xx` | 定量化している人が少なく、G1なら同日の前レースが使える |
| 2 | ペース展開の相互作用 | `F-1xx` | 馬単独では表現不能。G1で寄与が大きい |
| 3 | タイム指数（馬場差補正） | `F-3xx` | 市場は着順を見て内容を見ない |
| 4 | 調教 | `F-4xx` | 効くがデータ入手コストが高い |
| 5 | 血統 | `F-2xx` | 効くが既にオッズに厚く織り込み済み |
| 6 | 騎手・厩舎 | `F-7xx` | 交絡除去しないとむしろ有害 |

**優先度1は暫定である（`D-022`）。** 当初「内外バイアス」を測るつもりだったが、ラチからの横位置は公開データに存在せず、測れるのは通過順位ベースの脚質バイアスに留まる。当初想定より狭い範囲しか捉えられないため、実データで効果を確認するまでこの順位は仮のものとする。

## 3. G1固有の性質

`D-001` でG1に限定したことにより、一般的な競馬予想モデルの前提が一部崩れる。
**一般的な予想モデルの記事はハンデ戦や条件戦を前提にしていることが多く、そのまま持ち込むとG1では効かない特徴量に重みを割くことになる。**

### 効きにくくなるもの

| 特徴量 | 理由 |
|---|---|
| 斤量 | G1は定量・馬齢重量が中心で分散が小さい。ハンデ戦と真逆で情報量が低い |
| 前走着順 | 前哨戦は叩き台。本番との結びつきが弱い |
| クラス実績の絶対値 | 全頭が実績馬なので差が縮小する |

### 過去走を持たない馬が来る

**G1限定という設計に固有の問題。** ジャパンカップ・マイルCS・有馬記念・高松宮記念などには外国馬が出走し、交流を経た地方所属馬も出てくる。これらの馬は中間スキーマに過去走が1行も存在しない。

結果として `F-101`（逃げ意欲）も `F-103`（ペース適性）も `F-302`（補正タイム）も**すべて欠損**する。素朴に「データがないから低評価」とすると、**強い外国馬を必ず切るモデル**になる。`F-901`（レース内相対化）も、欠損馬を含むと平均・標準偏差が歪む。

条件戦には外国馬は来ないため、一般的な競馬予想モデルの解説にはこの論点が現れない。扱いは `018-cold-start.md` で定める。

### G1は均質な24競走ではない

**「G1」をひとつの塊として扱うと、使えるデータも効く特徴量も違うものを混ぜることになる。**

| 区分 | 競走数 | 何が違うか |
|---|---|---|
| 2歳G1 | 3 | **過去走が2〜5走しかない。** 過去走集計系（`F-101` `F-103` `F-302`）がほぼ機能しない |
| 3歳限定G1 | 7 | キャリアが浅い。トライアルが本番に直結するため**前走着順はむしろ効く**（下記） |
| 古馬芝G1 | 12 | 上の「効きにくくなるもの」がそのまま当てはまる中心層 |
| ダートG1 | 2 | 馬場状態の意味が芝と逆（水を含むと速くなる）。適性が芝と断絶している |

**上の「効きにくくなるもの」の表は、主に古馬芝G1を念頭に置いている。** 3歳クラシックでは前走（トライアル）の着順が本番と強く結びつくため、「前走着順は効かない」をそのまま適用すると誤る。

区分ごとに特徴量の効き方が変わることを前提に設計すること。`D-003` で全レース学習にしているのは、この分散を吸収する意味でも効いている。

### 逆に効きやすくなるもの

- **展開**（実力伯仲のため相対的な寄与が増す）
- **多頭数ゆえの枠順バイアス**
- **ローテーション**（前哨戦経由か直行か）
- **乗り替わり**（G1は主戦以外の有力騎手が乗る機会が多い）

## 4. 特徴量カタログ

### 確定時刻（全特徴量に付与する属性）

`D-028` により、すべての特徴量は**いつ確定するか**を属性として持つ。予測経路（`D-024` の暫定／本命）がどの特徴量を使えるかは、この属性で決まる。**特徴量を名指しで列挙しないこと。** 列挙は特徴量が増えるたびに漏れる。

| 値 | 意味 |
|---|---|
| `水曜` | 最終追い切り後。出走予定メンバーが判明している |
| `木曜` | 出馬表・枠順確定後 |
| `当日 T-<分>` | 当日。`T` は発走時刻。分が未確認のものは `T-?`（`Q-019`） |

**合成特徴量の確定時刻は、入力のうち最も遅いものに揃う。**

| 特徴量 | 確定時刻 | 備考 |
|---|---|---|
| `F-101` 逃げ意欲 | `木曜` | 過去走集計。メンバー確定で入力が揃う |
| `F-102` 想定ペース | **`当日 T-?`** | **馬場状態（`F-804`）を入力に含むため** |
| `F-103` ペース適性 | `木曜` | 過去走集計 |
| `F-104` 展開交互作用 | **`当日 T-?`** | `F-102` に従う。**Stage 2 の中核が当日情報に依存する** |
| `F-2xx` 血統 | `木曜` | |
| `F-301` 馬場差推定 | `木曜` | 過去レースから推定。原則7により as-of で切る |
| `F-302` `F-303` | `木曜` | 過去走集計 |
| `F-4xx` 調教 | `水曜` | 取得は `P-4`（`D-005`） |
| `F-501` 当日脚質バイアス | **`当日 T-?`** | 同日先行レースの確定後。対象レースのR番号で使える本数が変わる |
| `F-502` 当日時計傾向 | **`当日 T-?`** | 同上 |
| `F-503` 開催週次・柵移動 | `木曜` | 開催前に確定 |
| `F-601` 反動リスク | `木曜` | 前走情報 |
| `F-602` ローテーション | `木曜` | |
| `F-603` 馬体重 | **`当日 T-?`** | 当日発表 |
| `F-7xx` 人的要因 | `木曜` | 騎手確定が木曜 |
| `F-801` 枠順 | `木曜` | |
| `F-802` コース・距離適性 | `木曜` | |
| `F-803` レース基礎情報 | `木曜` | 天候・馬場状態を `F-804` に分離した後の残り |
| `F-804` 当日の天候・馬場状態 | **`当日 T-?`** | 予報値は別列（`D-029`） |

**`当日` のものは `T-15`（`D-024` の締切）に間に合うかが確定していない。** `T-?` は「当日に確定するが、発走何分前かを確認していない」ことを表す。`Q-019` の確認対象。

### F-1xx ─ 展開・ペース（今井雅宏系、ラップ理論）

> **プロの思考**：「逃げ馬が3頭、番手も揃った。ハイペース必至で、瞬発力型より持続力型が生きる」

#### F-101 逃げ意欲スコア

```python
逃げ意欲 = 過去走の (1角通過順 / 頭数) の下位分位点
```

4角ではなく**1〜2角の位置取り**で測る。4角は結果であり意欲ではないため。
平均ではなく**分位点**を使う。出遅れた凡走に引きずられないようにするため。
分母の頭数は `n_starters`（実出走頭数）を使う（`D-012`）。

**`corners` の要素数は距離とコース形態によって変わる。** マイル以下の多くのコースは1〜2角を通らず3・4角しか記録されない。新潟直線1000mにいたってはコーナーが無い。

**適用できないG1は「短距離だけ」ではない。** マイル以下のG1（高松宮記念・スプリンターズS・桜花賞・NHKマイルC・安田記念・マイルCS・阪神JF・朝日杯FS・ヴィクトリアマイル・フェブラリーS）に東京2000mの天皇賞秋を加えると、**24競走のうち4割強で1角の通過順が存在しない**（正確な該当数は `Q-011` の実データ確認で裏を取ること）。

**3角・4角で代用してはならない。** 結果を意欲として読むことになり、特徴量の意味が反転する。要素数が足りないレースは入力なしとして扱う。

#### F-102 想定ペース指標（Stage 1の出力）

```python
想定ペース = f(F-101上位馬の頭数, 距離, コース形態, クラス, 馬場状態)
```

**Stage 1モデルの目的変数**は実測ラップ（前半3F/5F、後半3F、前後半バランス）。
学習時のみ実測ラップを使い、推論時はメンバー構成から予測する。
対象レースの実測ラップを特徴量に混入させることは**リークであり厳禁**。

#### F-103 ペース適性（持続力型 / 瞬発力型）

```
各過去走について:
  そのレースのペース指数 p_i と、その馬の着差 d_i を記録
  → d_i を p_i に回帰した傾き β が「ペース適性」
     β > 0 : ハイペース得意（持続力型）
     β < 0 : スロー得意（瞬発力型）
```

**サンプルが5〜10走しかないため、階層ベイズで全体平均に縮約しないと使い物にならない。**

**内生性に注意（`Q-016`）。** 逃げ馬・先行馬は**自分でそのペースを作っている**。オーバーペースで飛ばして失速した馬は「ハイペースに弱い」と記録されるが、そのハイペースは本人が作ったものであり、適性ではなく自壊を測っている。差し・追込馬は他馬が作ったペースを受ける側なので影響は小さい。脚質（`F-101`）と β が交絡するため、対処を決めるまでこの特徴量の値を額面通りに読まないこと。

#### F-104 展開交互作用

`F-102`（想定ペース）× `F-103`（ペース適性）の交互作用項。
Stage 2の中核となる特徴量。

### F-2xx ─ 血統（亀谷敬正系）

> **プロの思考**：「この種牡馬は道悪と直線の長いコースで一変する。前走からの条件変化が鍵」

**最大の課題は次元の高さ。** 現役種牡馬は数百頭あり、one-hotにすると即座に過学習する。

#### F-201 種牡馬embedding（推奨実装）

```python
sire_id → 8〜16次元の埋め込み → 条件ベクトルとの交互作用
```

「似た特性の種牡馬」から情報を借りられるため、新種牡馬・少産駒でも機能する。
母父（damsire）も同様に扱う。

#### F-202 種牡馬の条件別成績（階層ベイズ縮約）

embeddingを使わない場合の代替。

```python
θ_sire = (n · x̄_sire + k · μ_global) / (n + k)
#   産駒数 n が少ない種牡馬ほど全体平均 μ に寄る
```

#### F-203 条件変化適性

亀谷理論の「条件変化への適性」の形式化。

```
前走条件と今走条件の差分ベクトル × 種牡馬embedding の交互作用
```

差分の対象：距離、芝/ダート、コース形態、馬場状態。

#### 注意

血統は競馬ファンに人気があるぶん**既にオッズへ厚く織り込まれている**。ここ単体で市場を超える期待値は高くない。
効かせるなら「血統 × 馬場状態」「血統 × 開催後半の荒れ馬場」など、**織り込みが粗くなる複合条件**を狙う。

### F-3xx ─ タイム指数（西田式、IDM系）

> **プロの思考**：「時計は平凡だが、あの馬場・あのペースなら価値がある」

```
補正タイム = 走破タイム − 基準タイム − 馬場差 − ペース補正 − 斤量補正
```

#### F-301 馬場差の推定（技術的な核心）

混合効果モデルでレース効果を推定し、差し引く。

```python
走破タイム ~ 距離 + クラス + (1 | レースID) + (1 | 馬ID)
#            レースIDのランダム効果 ≈ 馬場差 + 展開
#            馬IDのランダム効果     ≈ その馬の真の能力
```

**ここの精度がそのままモデルの強さを決める。**

**レース効果は馬場差だけではない。** 実際には「馬場差 + 展開 + **そのレースのメンバーレベル**」が同じ効果に吸われる。強いメンバーが揃ったレースは速い時計が出るが、それは馬場が速いからではない。

原理的には、同じ馬が複数レースに出ることを通じて馬効果とレース効果は識別できる。ただし**接続が弱い部分集団では分離できない**ため、G1だけを取り出して推定してはならない。`D-003` に従い全レースで推定する。

#### F-302 補正タイムベースの能力値

`F-301` の馬IDランダム効果、および補正タイムの過去走集計（最高値・直近平均・トレンド）。

市場は**着順**を見るが**内容**の評価は粗い。「厳しい展開で負けたが時計は優秀」という馬を機械的に拾えるため、自作する価値が最も高い領域のひとつ。

#### F-304 中央値ベースの速度指数

`F-301`/`F-302` と同じ「馬場差で補正した走破時計」を、混合効果モデルではなく**中央値**で推定する別ルート（`D-123`）。

```
base(surface, distance, class_key, month)  その月より前の time_sec の平均・標準偏差
resid = time_sec − base
tv(date, course, surface)                  その日その場その馬場の resid の中央値
spd   = −(resid − tv) / base_sd            正が速い
```

`class_key` は `COALESCE(grade, race_class, 'その他')`。`race_class` は `G1`〜`G3`・`L` を `'オープン'` に丸めるため `grade` を優先する。

馬ごとの特徴量は過去走（`race_date < target_race_date`）の集約で、`fspd_best` / `fspd_mean` / `fspd_last` / `fspd_recent3` / `fspd_n` の5列。大差負けが平均を壊すため `±5` でクリップしてから集約する。

**`F-301`/`F-302` の代わりに使う。** あちらは推定が破綻して既定無効（`D-110`）。中央値ベースは標本の少ない馬で効果量が発散する問題（`D-108`）が構造的に起きない。

**市場を超える情報は持たない**（`D-120`）。単独モデルの精度向上のために入れる特徴量であり、`R-023` の達成手段ではない。

#### F-303 上がり3F関連

上がり3Fタイム、レース内の上がり順位、ペースを考慮した上がり評価。

### F-4xx ─ 調教

> **プロの思考**：「坂路50秒台は速いが、この馬にとっては平凡。前走前より0.8秒詰めてきたのが良い」

**取得には JRDB（CHA / CYB）が必要**（`D-005`）。

#### F-401 追い切りタイムの馬内z-score

```python
追い切り評価 = (今回の坂路4Fタイム − その馬の過去追い切り平均) / その馬の標準偏差
```

**絶対値ではなく馬ごとのベースラインからの乖離で見る。** 絶対値は厩舎の調教方針差でバイアスがかかるため。

#### F-402 併せ馬評価

相手馬の格 × 先着/遅れ（着差）。

#### F-403 調教量・強度

追い切り本数、一週前追いの有無と強度、追い方（一杯 / 強め / 馬なり）。

### F-5xx ─ 馬場読み（G1限定だからこそ使える）

> **プロの思考**：「今日は内が伸びない。開催5週目で内ラチ沿いが荒れている」

**G1限定という設計の隠れた利点がここにある。** G1は基本メインレース（10R〜11R）なので、**同日の同開催で先に行われたレースの結果が使える**。

#### F-501 当日の脚質バイアス（`D-022`）

```python
当日脚質バイアス = 同日・同競馬場・同芝/ダ の先行レースにおける
                   (上位馬の4角通過順位 / n_starters) の平均
```

**当初は「勝ち馬の4角通過ラチ位置」で定義していたが、この量は公開データに存在しない。** 取得できるのはコーナー通過順位（縦の並び）であって、ラチからの横位置ではない。内外バイアスは直接測る手段がないため当面あきらめ、**先行有利か差し有利か**を測る形に置き換えた（`D-022`）。

値が小さいほど前が残る馬場、大きいほど差しが決まる馬場を意味する。

#### F-502 当日時計傾向

```python
当日時計傾向 = 同条件レースの (走破タイム − 基準タイム) の平均
```

`F-501` `F-502` はいずれも**発走前に確定している情報でありリークにならない**。かつ市場が完全には織り込めていない可能性がある領域。人間は当日の馬場読みをするが、定量的にやっている人は多くない。

**リーク注意**：前後の判定は `(date, course, race_number)` で行い、`race_number <` の厳密不等号で絞る（`D-010`）。`<=` にすると対象レース自身が入り、**別競馬場を混ぜると複数場開催で前後関係が壊れる**。日付だけで同日レースを引くのは即リークである。

#### F-503 開催週次・柵移動

開催何週目か、Aコース / Bコース / Cコースの柵移動状態。芝の傷み具合はこれで大きく変わるため必須。

### F-6xx ─ 反動・臨戦過程（Mの法則系）

> 今井理論の核心の一つ「激走の後は凡走する」を、検証可能な形に書き下したもの。

#### F-601 反動リスク

```python
前走消耗度 = f(前走のペース, 前走の着差, 距離, 上がり順位)
人気超過度 = 前走人気 − 前走着順      # 大きいほど「激走」
反動リスク = 人気超過度 × exp(−レース間隔 / τ)
```

**真偽はデータが答える。`P-3` で仮説として投入し、効かなければ捨てる。**

#### F-602 ローテーション

前走からの間隔（週）、放牧明けか連戦か、前走のグレード。

G1固有の論点として、**前哨戦を叩いたか直行か**がある。近年は直行がトレンドであり、直行は陣営の自信の表れとも解釈できる（`F-703` と関連）。

#### F-603 馬体重

### F-7xx ─ 人的要因（交絡に注意）

# 良い例：人気を統制した残差

### F-8xx ─ 基礎・コース

#### F-801 枠順バイアス

#### F-803 レース基礎情報

#### F-804 当日の天候・馬場状態

#### F-805 出走馬の基礎情報

`race_level`: `False`

### F-9xx ─ 横断処理（全特徴量に適用）

これらは個別の特徴量ではなく、**上記すべてに適用される変換規則**である。

#### F-901 レース内相対化（最重要）

競馬は「絶対的に速いか」ではなく「**そのレースの中で誰が一番速いか**」の相対問題。
全ての連続値について、生値と相対値の**両方**を持たせる。

```python
x_rel  = (x - race_mean(x)) / race_std(x)   # z-score
x_rank = rank_within_race(x) / n_starters   # 外れ値に強い
```

**Stage 2の入力は原則すべて相対値であるべき。** G1は能力が拮抗しているぶん、絶対値の差がほぼ意味を失うため特に重要。

**ただしレース単位の変数には適用しない（`D-021`）。** `F-102`（想定ペース）のようにレース内で全馬共通の値を取る変数を相対化すると、z-score が 0/0 になる。さらに `F-104 = F-102 × F-103` を相対化すると

```
z(F-104) = sign(F-102) · z(F-103)
```

に潰れ、**想定ペースの大きさが完全に消える**。`F-102` が 2.7 でも 40.0 でも結果は同一になり、Stage 1 が何を予測しても Stage 2 に届かなくなる。相対化するなら `F-103` の側だけに適用し、交互作用はその後に取る。

#### F-902 縮約（shrinkage）

種牡馬・騎手・厩舎・コース適性など、**すべての集計特徴量に適用する**。
サンプル数が不均一なため、生の平均値を使うと少サンプルのノイズを拾って必ず過学習する。

```python
θ = (n · x̄ + k · μ_global) / (n + k)
```

#### F-903 高次元カテゴリのembedding化

種牡馬・母父・騎手・厩舎。one-hotは避ける。

## 5. リーク防止の原則

`P-1` でテストコードとして実装し、CIで検証する対象。

1. 使ってよいのは**発走時点で確定している情報のみ**
2. 過去成績の集計は `race_date < target_race_date` で厳密にフィルタする
3. **同日開催の別レースは原則除外**。ただし `F-501` `F-502` は例外として、**対象レースより前に発走したレースに限り**使用を許可する。判定は `(date, course, race_number)` の厳密不等号で行う（`D-010`）。この例外を他の特徴量に広げない
4. 「その馬のその後の成績」に由来する集計特徴量は禁止
5. 対象レースの実測ラップ・走破タイム・着順は特徴量に含めない（Stage 1の目的変数としてのみ使用）
6. オッズは予測に使わない（`D-002`）。過去オッズの利用は `F-701` の範囲に限定する
7. **集計統計量の推定期間も as-of で切る。** `F-902` の `μ_global`、`F-301` の混合効果モデル、`F-201` の種牡馬embedding、および **Stage 1（レース質予測モデル）の学習**を**全期間一括で行うと、行ごとの日付フィルタが完璧でも未来がリークする**。fold の学習期間内だけで推定し直すこと。Stage 1 が対象に入るのは、その出力 `F-102` が Stage 2 の入力になるため（`D-054`）

原則7の検査は「未来のデータを足して再計算したとき、過去分の特徴量の値が1ビットも変わらないこと」で定式化できる。これは日付フィルタの検査では捕まらないため、`tests/test_leakage.py` の中核テストに据える。
