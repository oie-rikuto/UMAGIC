## Q-003 予測を出すタイミング

**状態**: Resolved → `D-024`

**問い**: どの時点で予測を確定させるか。使える特徴量が変わる。

**選択肢**:

| タイミング | 使えるもの | 使えないもの |
|---|---|---|
| 最終追い切り後（水） | 出走予定メンバー、最終追い切り(`F-4xx`) | 枠順、当日情報 |
| 出馬表・枠順確定（木） | + 確定メンバー、枠順(`F-801`) | 当日情報 |
| 当日（発走前） | + 馬体重(`F-603`)、当日馬場バイアス(`F-501`,`F-502`) | — |

**この表は当初、最終追い切りを枠順確定より後に置き、出馬表確定と枠順確定を別日として書いていたが誤りだった。**
JRAでは最終追い切りが開催週の水曜で枠順確定より前、出馬表確定と枠順確定は同じ木曜である。
実運用に入る前に、現行のスケジュールを一度確認すること。

**必要な情報**: 運用上どう使いたいか（前日までに検討したいのか、当日直前で良いのか）。

**ブロックするもの**: `016-inference.md`（当日の予測実行フロー）。また `F-501` `F-502` は当日でないと使えない。これらは市場を超える余地が最も大きいと見込んでいる領域（`domain-knowledge.md` 2節）のため、**当日予測を前提にしないとモデルの中核が成立しない**可能性がある。

**暫定方針**: 当日予測を基本とし、枠順確定時点の「暫定予測」も出せる二段構えを想定しておく。

**解決**: `D-024`（2026-08-15）。暫定方針どおり二段構えを採用し、当日の本命予測に**発走15分前**という締切を追加した。締切を満たせるかは未検証のため `Q-019` に切り出した。上記の「実運用に入る前に現行スケジュールを確認する」は依然として有効。

## Q-007 Stage 1 の目的変数の具体形

**状態**: **Resolved → `D-087`**（2026-08-19）

**問い**: `F-102`（想定ペース）を予測するStage 1モデルの目的変数を何にするか。

**候補**:
- 前半3F / 前半5F の絶対タイム
- 前半後半バランス（前半3F − 後半3F）
- ペース指数（基準タイムからの偏差）

**必要な情報**: 実データでの検証。Plackett-Luce で展開した複勝確率と実際の複勝率を人気帯別に比較すれば、偏りの大きさと形が分かる。**モデルを作る前に市場データだけで確認できる。**

**状態**: **Resolved**（2026-08-25、`D-104`〜`D-107`）

**解決**: 実装方法を **自前の交互反復**（レース効果と馬効果を交互に更新し、縮約強度は分散成分から `k = σ²_誤差 / σ²_効果` として決める）に確定した（`D-104`）。`statsmodels` の `MixedLM` と `PyMC` は、実データで確定した規模（464,765出走行・レース33,236水準・馬53,712水準の交差ランダム効果）に対して現実的でないため脱落した。

以下は解決前の記録として残す。

**状態（旧）**: Open ／ **優先度: 高**（`Q-008` から切り出し）

**問い**: `F-301`（馬場差推定）の混合効果モデルと、`F-103`（ペース適性）・`F-202`（種牡馬の条件別成績）の階層ベイズを、どのライブラリ・どの推定方法で実装するか。

**候補**:

| 方法 | 見込まれる性質 |
|---|---|
| statsmodels の `MixedLM`（頻度論） | 標準的。大規模なランダム効果でのメモリ・時間は**未検証** |
| PyMC（ベイズ） | `F-902` の縮約と考え方が一貫し、少サンプルの扱いが正確。最も計算コストが重い |
| 自前の反復推定（交互に平均を除去する等） | 軽い。ただし不確実性の定量化ができない |

**論点**:

- `domain-knowledge.md` は `F-301` について **「ここの精度がそのままモデルの強さを決める」** と記録しており、安易に粗い方法へ倒せない
- 規模が大きい。`architecture.md` 1.1 によればJRA全体で年間約3,450競走・20年で**約90万出走行**。レースIDのランダム効果はレース数と同じ水準になる
- **リーク防止の原則7により fold ごとに再推定が要る。** walk-forward を複数年ロールで回すと、推定回数が fold 数だけ掛かる
- `D-027` はバックテストの実行時間に上限を設けないが、**現実的に終わるかは別問題**である
- `F-301` は「全レースで推定する」ことが `D-003` により必須。G1だけを取り出して推定してはならない

**必要な情報**: 実データを取り込んで規模を確定させたうえで、短い学習期間で試算する。**`P-0` が終われば着手できる。**

**データ前提の確認（2026-08-25、実施済み）**: 実装方法を選ぶ前に、**そもそもデータが馬場差を識別できるか**を10年分（2015年以降、33,236レース・467,927出走行）で確認した。結果は全項目クリアで、**この問いに残るのは実装方法の選択のみになった**（データ面の障害は無い）。

| 確認項目 | 結果 |
|---|---|
| `runners.time_sec` のカバー率 | **100.0000%**（完走扱い 464,764行すべて。欠損は `競走中止`/`競走除外`/`出走取消` のみで、いずれも走破タイムが存在しない正常系） |

| 2セッション以上を走った馬 | 49,509 / 53,712（**92.2%**）。3セッション以上は81.3% |
| **セッション二部グラフの連結成分** | **1個**（5,764セッションすべてが単一成分・孤立成分ゼロ） |
| 芝ダ×距離の組み合わせ | 30（レース数30未満の薄い組み合わせは6件） |

**連結成分が1個であることが決定的。** 「走破タイム ≒ 馬の能力 + セッションの速さ + 誤差」という形が識別可能であるためには、セッションを跨いで走る馬を通じて二部グラフが連結している必要がある。分裂していれば成分ごとに定数のズレが残り、成分をまたぐ比較には基準の恣意的な固定が要る。実測では**10年分が単一成分**であり、`F-302` を「全期間で相互比較可能な単一尺度」として構成できる。この結果は `013-track-variant.md` の仕様に直接効く（基準固定の節が不要になる）。

**なぜ設計より先に確認したか**: `Q-035`（端数距離のラップ本数）で、仕様の前提（`D-087` の「末尾3本＝600m」）を実データで確認せずに式を書いていたら手戻りになる、という経験をしている。混合効果モデルの実装方法をどれだけ丁寧に選んでも、データが識別しない構造なら推定値はノイズにしかならない。

## Q-038 orchestration層の学習が `R-021`（ビット完全な再現性）を満たしていない可能性

**状態**: Resolved（大部分。2026-08-24）

**解決**: 原因は `polars` の `join` ではなく `F-103` の `_ols_slope()` にあった。`p_i`（DuckDB の並列 `AVG()` 集計を経由）の分散が極小な馬では `beta = cov_xy / var_x` が悪条件になり、通常は無害な浮動小数点誤差（`~1e-14`）が大きく増幅されていた。`beta` は全馬共通の `mu_global`（累積平均）に混ざるため、少数の不安定な `beta` の誤差が `f103` を持つ行の約60%（144,561行中87,343行）に伝播していた。`_ols_slope()` に分散の下限ガード（`MIN_VAR_X=1e-6`）を追加し、`f103` の実行間の最大差を `1.21e-7` → `3.15e-11`（約3800分の1）に縮小した（`D-102` に詳細）。

**残る差（`~1e-11`〜`~1e-16`）は通常のDB並列集計に伴う浮動小数点丸め誤差であり、完全に除去するにはDB接続のシングルスレッド化が必要**（費用対効果が見合わず見送った、`D-102`）。`R-021` は「この程度の丸め誤差を除く範囲」で満たすものとして扱う。

**この修正より前に得た `R-023`・年代別内訳の数値（`docs/tasks.md`）は不安定だった `f103` を経由しているため、参考値として扱うこと。** 確定させるには修正後の再実行が必要。

以下は解決前の記録として残す。

**状態（旧）**: Open ／ **優先度: 高**

**問い**: 同一の入力・同一のコード・同一の乱数シードで `run_p3_completion_check()` を2回実行したところ、**G1のモデルLogLossが一致しなかった**（`2.2985` → `2.3270`、約1.2%の差）。`all` 母集団でも小さいが差が出た（`2.2197` → `2.2207`）。`R-021`（同一入力から同一出力が再現できる）に違反している可能性がある。

- `lightgbm` 側は `deterministic=True` / `force_row_wise=True` / `num_threads=1` を設定済みで、**同じ行順・同じグループ配列を与えれば**ビット完全になるはずの設定
- **疑わしいのは polars の `join` が既定で行順を保証しないこと。** `orchestration.py` の `assemble_stage2_matrix()` 内で `build_features()` の出力に `f102`・`n_starters` を左結合しているが、`build_features()` 自身の末尾でのみ整列しており、**その後の複数回の結合のたびに整列し直していない**。DuckDB のクエリ実行順（並列ハッシュ結合など）がプロセスごとにわずかに変わり、結合後の行順がぶれ、`race_group()` が前提とする `(race_id, horse_id)` の連続性が崩れている可能性がある
- `G1` 母集団（135件、少標本）の方が `all`（23,224件）より相対誤差が大きいことは、影響がごく一部の行に限られる場合の挙動と整合する

**状態**: Open（`F-102`単体の精度・`F-104`が効かない理由の両方を診断済み。`F-102`は構造的制約と判断し対処不要、`F-103`/`F-104`側の疑いは`Q-044`に切り出した） ／ **優先度: 中**

## Q-042 レース効果に吸われる「メンバーレベル」を分離すべきか

**状態**: Open ／ **部分的に実証（`D-111`/`D-112`）。`all`側の追加診断も完了（`D-114`）、優先度を中に下げる**

**論点（未解決のまま残る）**:

- 原理的には、メンバーレベルは出走各馬の馬効果の平均そのものであり、`u_j` から分離するには反復の中で `u_j - mean(v_i over i in j)` を取ればよい。ただしこれは馬効果の定義と循環するため、単純には収束しない
- `F-502`（当日時計傾向）が「クラス別基準タイム」を必要としており（`Q-031`）、その基準タイムを `u_j` から作るなら分離が要る

**ブロックするもの**: `Q-031`（`F-502` のクラス別基準タイム）。`F-302` の再有効化（`all`側の悪化を解消すること）はこの論点だけでは解決しない。`F-301`の推定方法自体の再設計が要る、より大きな課題として残る。

## Q-044 `F-103`（ペース適性）の縮約は`F-302`と同型の未ロバスト化問題を抱えているか

**状態**: Resolved（`D-116` / `D-118`）。**同型であることは実証され、対処候補5つはG1 OOF 3 fold でいずれも採用ラインに届かなかった。`F-103` は「壊れているが不活性」——実害も改善余地も測定限界以下**

**問い**: `F-103`（`src/umagic/features/f103.py`）は馬ごとに過去走の `d_i ~ p_i` 単回帰の傾き `β` を計算し、`F-902`（`shrink()`）で縮約する。この`β`推定・縮約が、`F-301`（`D-108`/`D-114`で外れ値耐性の低さが確認済み）と同じ構造的弱点を持っているのではないか。

**根拠（2026-08-25、`D-115` / `data/diag12_q040_f103_f104.py`）**:

- `f103`の生値（relativize前、`f103_unavailable=0`のみ）は std=14.78・範囲 `[-1192.11, +1653.31]`（fold0学習期間、n=144,904）という極端な尺度を持つ
- `f103_z`/`f104`とlabelのプールSpearman相関は train −0.0096〜+0.0040・valid +0.0090〜+0.0099と、既知の有効特徴量（`last3f_recent_z`・`f601_finish_pos_prev_z`）の1/13〜1/30の大きさで、**train/validで符号すら安定しない**
- `f102`（想定ペース水準）でレースを三分位に分けても、`f103_z`とlabelの相関にビン間の一貫したパターンは見られず、`F-104`の交互作用仮説（想定ペースが極端なほどペース適性が効く）を支持しなかった

**実証（2026-08-25、`D-116` / `data/diag13_q044_f103_beta.py` / `data/diag14_q044_shrink_effect.py`）: 同型であることを確認した。**

- **外れ値は少標本に集中する**: `β` の std は `n_valid_pairs=2` で 131.531（範囲 `[-5254.91, +5787.75]`）、`n>=21` で 3.031（範囲 `[-21.65, +19.33]`）と **43倍**違う。過去走5走以下が全体の **42.7%**（132,409/310,099行）
- **機構は `var_x`**: `var_x<1e-4` の層は std=516.574・max|β|=5787.75。`MIN_VAR_X` を `1e-3` に上げるだけで**除外は3.1%にとどまり** std が 50.069→12.300・max|β| が 5787.75→235.09 に落ちる
- **縮約は無力**: `k=5` の `shrink()` は `n=2` で `β` の29%を残すため、std は 50.069→14.859（3.37倍しか縮まない）
- **決定的な実例**: `horse_id=50587`（`n_valid_pairs=2`・`var_x=1.21e-06`・`β=-4171.44`）→ `f103=-1192.15`。`D-115` が報告した fold 0 行列の `f103` 最小値 `-1192.11` の正体
- **`mu_global` 自体も歪む**: 単純累積平均 `-0.4274` に対し中央値 `-0.0583`（7.3倍）
- **`n=2` は二峰的なごみ**: 8.96% が `β` ちょうど `0`（`D-064` の着差が離散的で、2走同着差なら厳密に0になる）、残りは ±5788 まで伸びる裾

**対処候補（いずれも未検証。採否は下記の規律で決める）**:

1. **`MIN_VAR_X` を引き上げる**（`1e-3`〜`1e-2`）。最も安く効果が大きいが、`D-102` が設定した本来の目的（数値誤差の増幅防止）とは別の目的を同じ定数に負わせることになるため、**定数を分けるか `D-102` を改訂するかの判断が要る**
2. **`n_valid_pairs` の下限を設ける**（例: 4以上）。`var_x` は標本数の代理でしかなく（`var_x<1e-4` の `n_valid` 中央値は 2.0、`>=1e-1` では 13.0）、**2〜3点の回帰は残差自由度が0〜1で原理的に信号と雑音を分離できない**。こちらの方が原理的
3. **`mu_global` と `k` の再設計**。縮約先を中央値にし、`k` を標本数ではなく**推定精度**（`β` の標準誤差は `1/sqrt(var_x)` に比例）で決める。これが最も筋が良いが最も手が要る

**候補の比較結果（2026-08-25、`D-118` / `data/diag16_q044_g1_oof.py`）: 全て不採用。**

**向きが3 fold 揃う候補は1つも無く、G1側は30比較すべてでCIが0を跨いだ。** 個別に有意だったのは3件のみで、いずれも `all` 側（`D-101` が選定に使うなと言っている指標）。`D-113` が満たした採用条件の入口にすら届かない。

**`mu_median` は明確に棄却。** fold 間の振れが最大（+0.1185 / −0.0580 / +0.0481）で、`all` 側でも符号が反転して両方向に有意になった。縮約先を動かすと安定するどころか不安定化する。

**最も重要: `drop`（丸ごと除去）も base と区別がつかない。** `D-116` が `β` の統計的破綻を実証したにもかかわらず、除去しても測定可能な変化が起きない。**`F-103` は有害なのではなく不活性**であり（`D-115` の「label とほぼ無相関」と整合）、`cat_smooth`/`cat_l2`（`D-113`）を含む現在の設定下で LightGBM が実質的に無視できている。

**期待できる効果量の見積もり（過大評価しないこと）**: `D-103` の fold 0 アブレーションで `F-103` を除いた改善は `-0.0040`。`R-023` のギャップは G1 で 0.4173（モデル 2.3085・市場 1.8912）であり、**`F-103` の修正が埋めるのはその1%程度**。`D-103` が指摘した本丸（モデルが市場に上乗せ情報を持たない）を解くものではない。

**論点: `Q-042` と同一の設計課題である。** `F-301`/`F-302`（`D-108`/`D-114`）と `F-103`（`D-116`）は、**「per-entity の回帰係数・効果量を標本数だけで縮約する設計が、推定精度の違いを無視するため破綻する」という単一の失敗様式**を、独立した2つの特徴量で再現したものである。共通の縮約基盤（精度重み付き縮約）として設計し直す案は残るが、**`D-118` により `F-103` 単体ではその投資を正当化できないことが分かった**（壊れていても不活性なので、直しても測定可能な改善が出ない）。`F-301`/`F-302` 側（`Q-042`）で効果が実証されて初めて `F-103` にも展開する、という順序にする。`D-051`（階層ベイズを対象外とし `F-902` の単純式に統一）を覆すかどうかも、その時点で判断する。

**ブロックするもの**: 何もブロックしない。`D-118` で決着。`F-103` の実装上の欠陥（`D-116`）は事実として残るが、`R-023` に対する実害・改善余地ともに測定限界以下であり、**`R-023` の本丸（`D-103`: モデルが市場に上乗せ情報を持たない）とは無関係**である。
