## 目的

中間スキーマ（`001-schema.md`）から Stage 1 / Stage 2 の入力となる特徴量行列を組み立てる。`F-301`（馬場差推定）は `013-track-variant.md`、`F-4xx`（調教）は `P-4` に分離済みで、本仕様はそれ以外を扱う（`D-052`）。

## 入出力

```python
from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from typing import Literal, Protocol

import duckdb
import polars as pl

Timing = Literal["水曜", "木曜", "当日"]


@dataclass(frozen=True)
class FeatureSpec:
    name: str                        # 'F-101' など
    columns: list[str]               # この特徴量が出す列名
    timing: Timing
    minutes_before_post: int | None   # timing='当日' のときのみ。未確認は None（Q-019）
    race_level: bool                 # True ならレース内で全馬共通（F-901 を適用しない）


class FeatureRegistry(Protocol):
    def all(self) -> list[FeatureSpec]: ...
    def columns_for(self, route: Literal["暫定", "本命"]) -> list[str]: ...


def build_features(
    conn: duckdb.DuckDBPyConnection,
    *,
    as_of: date,
    race_ids: list[int] | None = None,
) -> pl.DataFrame: ...
```

`build_features` の契約は `004-leakage-test.md` が定める。要約すると以下。

| 項目 | 要求 |
|---|---|
| `as_of` | `as_of` 以降のデータを一切参照しない。集計統計量の推定期間も含む（`R-019`） |
| 戻り値 | `(race_id, horse_id)` で一意 |
| 決定性 | 同じ入力・同じ `as_of` でビット完全一致（`D-055`） |
| 集計順序 | 集約前に `(race_id, horse_id)` で整列する（`D-055`） |

## 仕様

### 共通規約

個別の特徴量定義より前に、すべてに適用される規則を定める。

#### 1. 過去走の範囲（原則2 / `R-019`）

```sql
-- 対象レース R（date=D, course=C, race_number=N）の馬 H について
SELECT ... FROM runners ru JOIN races r USING (race_id)
WHERE ru.horse_id = :H
  AND r.date < :D          -- 厳密不等号。同日は含めない
  AND r.date < :as_of      -- as_of 以降は存在しないものとして扱う
```

**`F-501` `F-502` のみが同日レースを参照できる（`D-010`）。** それ以外の特徴量が同日のレースを読んではならない。

#### 2. 集計の窓（`D-059`）

過去走を集計する特徴量は、**全履歴と直近N走の両方**を列として出す。

| 接尾辞 | 意味 |
|---|---|
| `_all` | 全履歴 |
| `_recent` | 直近N走。`N` は特徴量ごとの設定値 |

`N` の既定値は `P-3` のハイパーパラメータ探索で決める。本仕様では値を固定しない。

#### 3. 縮約（`F-902` / `D-051`）

集計特徴量には例外なく縮約を適用する。

```
θ = (n · x̄ + k · μ_global) / (n + k)
```

| 記号 | 意味 |
|---|---|
| `n` | その集計の標本数 |
| `x̄` | 生の平均 |
| `μ_global` | 全体平均。**対象行ごとに、その行自身のレース日付より前のデータのみで計算する**（`R-019`） |
| `k` | 縮約の強さ。特徴量ごとの設定値。既定値は `P-3` で決める |

**`μ_global` を全期間で計算してはならない。** `004-leakage-test.md` の `test_as_of_recomputation_invariance` が落ちる。

**`μ_global` は `build_features` 呼び出し単位の共有定数にしてはならない。** `as_of` だけで境界を引いた単一の値を全対象行に適用すると、**別の `as_of` で呼び出したときに、以前と同じ対象行の値まで変わってしまう**（`as_of` の間に新しいレースが1件でも増えれば、その分だけ全体平均が動くため）。`R-019` が求める「過去分の特徴量の値が1ビットも変わらない」を満たすには、対象行ごとに独立して「その行自身のレース日付より前」で母集団を切り直す必要がある。`n` と `x̄`（生の集計値）も同様に対象行ごとに計算する。

#### 4. レース内相対化（`F-901` / `D-021`）

`race_level=False` の特徴量について、生値・z-score・順位の**3列**を出す。

| 接尾辞 | 定義 |
|---|---|
| （なし） | 生値 |
| `_z` | `(x − race_mean(x)) / race_std(x)` |
| `_rank` | `rank_within_race(x) / n_starters` |

`race_std(x)` が 0 の場合、`_z` は `NaN` とする。

**`race_level=True` の特徴量には適用しない（`D-021`）。** `F-102` `F-104` `F-501` `F-502` `F-503` `F-803` `F-804` が該当する。適用すると `F-104` が

```
z(F-104) = sign(F-102) · z(F-103)
```

に潰れ、想定ペースの大きさが消える。

分母の頭数は `n_starters`（実出走頭数）を使う（`D-012`）。

#### 5. 欠損の表現（`D-058`）

補完しない。`NaN` のまま渡す。

| 列 | 意味 |
|---|---|
| `<feature>` | 値。計算できなければ `NaN` |
| `<feature>_unavailable` | `1` = **構造的に存在しない**／ `0` = それ以外 |

指示子は構造的欠損が起きうる特徴量にのみ付ける。取得漏れは `NaN` かつ指示子 `0` とし、`012-data-quality.md` が検出する。

#### 6. 集計順序の決定性（`D-055`）

集約の前に `(race_id, horse_id)` で整列する。並列実行や辞書の反復順に依存した加算順を作らない。

#### 7. 着差の数値化（`D-064`）

`runners.margin`（ソース表記の文字列）を馬身単位の数値に変換する。過去走の着差を使う特徴量（`F-103` の `d_i` など）は必ずこの表を経由する。

| 表記 | 数値（馬身） |
|---|---|
| 分数表記（`1/2` `3/4` `1.1/4` `1.1/2` `1.3/4` `3.1/2` 等） | 小数化（`1.1/4` → `1.25`） |
| 整数表記（`1` `2` `3` … ） | そのまま |
| `ハナ` | `0.05` |
| `アタマ` | `0.1` |
| `クビ` | `0.2` |
| `大`（大差） | `10.0`（打ち切り値） |
| `同着` | `0.0` |
| それ以外（`NULL`・未知の表記） | `NULL` |

### F-1xx 展開・ペース

#### F-101 逃げ意欲スコア

```python
# 対象馬の過去走それぞれについて
pos_ratio_i = corners[j] / n_starters_i
#   j は races.corner_nos[j] == 1 を満たす添字（D-043）
逃げ意欲 = quantile(pos_ratio, q)     # q は下位分位点。既定値は P-3 で決める
```

| 項目 | 規則 |
|---|---|
| 使うコーナー | **1角のみ**。`corner_nos` に `1` が含まれる過去走に限る |
| 3角・4角での代用 | **禁止**（`D-043`）。結果を意欲として読むことになる |
| 集約 | 平均ではなく分位点。出遅れた凡走に引きずられないため |
| 分母 | `n_starters`（`D-012`） |

**`corner_nos` に `1` を含まないレースでは計算できない。**

| 状況 | `f101` | `f101_unavailable` |
|---|---|---|
| 1角を含む過去走が1走以上ある | 値 | `0` |
| 過去走はあるが1角を含むものが無い | `NaN` | `1` |
| 過去走が無い | `NaN` | `0` |

`race_level`: `False`

#### F-102 想定ペース指標

Stage 1（`006-stage1-pace.md`）の出力を受け取る。本仕様は計算しない。

**対象レースの実測ラップを入力にしてはならない（`D-007` / 原則5）。** 実測ラップは Stage 1 の目的変数としてのみ使う。

`race_level`: `True`（レース内で全馬共通）

#### F-103 ペース適性

```python
# 対象馬の過去走 i について
p_i = 1 − mean(F-101 of 他の出走馬)     # D-061 / D-065
d_i = そのレースでの着差（数値化は共通規約7 / D-064）
β  = OLS(d_i ~ p_i) の傾き（過去走が2走未満なら計算不能。この場合 β=NaN）
F-103 = 縮約(β, n=過去走数, k, μ_global)                          # D-051
```

**`p_i` は自馬の寄与を除いて計算する（`D-061`）。** 自馬を含めると、逃げ馬が自分で作ったペースへの反応を適性として読むことになる。

**`p_i` の集約は他馬 `F-101` の単純平均を反転した値とする（`D-065`）。** `F-101` は小さいほど先行意欲が強いため、`1 −` で「大きいほどハイペース」という向きに揃える。他の出走馬全員の `F-101` が欠損している過去走は、その過去走を回帰から除外する（`D-065`）。

**`F-101` の欠損が伝播する。** `p_i` は他馬の `F-101` から算出するため、`corner_nos` に `1` を含まないレースでは `p_i` が計算できず、`F-103` も `NaN` になる。

| 状況 | `f103` | `f103_unavailable` |
|---|---|---|
| `p_i` が計算できる過去走が2走以上ある | 値 | `0` |
| 過去走はあるが `p_i` が計算できる走が1走以下 | `NaN` | `1` |
| 過去走が無い | `NaN` | `0` |

`race_level`: `False`

#### F-104 展開交互作用

```python
F-104 = F-102 × F-103_z
```

**`F-103` の側だけを相対化してから積を取る（`D-021`）。** 積を取った後に相対化しない。

`race_level`: `True`

### F-5xx 馬場読み

#### F-501 当日の脚質バイアス

```sql
-- 対象レース（date=D, course=C, race_number=N, surface=S）について
SELECT ru.corners, r.n_starters
FROM races r JOIN runners ru USING (race_id)
WHERE r.date = :D
  AND r.course = :C          -- 別競馬場を含めない（D-010）
  AND r.surface = :S
  AND r.race_number < :N     -- 厳密不等号。対象レース自身を含めない
  AND ru.finish_pos <= 3
```

```python
当日脚質バイアス = mean(4角通過順 / n_starters)   # 上位馬について
```

### 確定時刻の登録（`D-028` / `R-028`）

`FeatureRegistry` は全特徴量の `timing` を持つ。値は `domain-knowledge.md` 4節の表に従う。

| `timing` | 該当する特徴量 |
|---|---|
| `木曜` | `F-101` `F-103` `F-2xx` `F-302` `F-303` `F-503` `F-601` `F-602` `F-7xx` `F-801` `F-802` `F-803` |
| `当日` | `F-102` `F-104` `F-501` `F-502` `F-603` `F-804` |

**合成特徴量の `timing` は入力のうち最も遅いものに揃える。** `F-104` が `当日` なのは `F-102` に従うため。

`minutes_before_post` は `当日` のもの全てで `None`（`Q-019`）。

## 制約

- **予測対象レースのオッズを特徴量にしない（`D-002` / `R-018`）。** `F-701` `F-703` が使う**過去レースの**人気のみが例外（`Q-006`）
- **学習はG1に絞らない（`D-003`）。** 特徴量生成に `grade` によるフィルタを入れない。G1特化は `race_class`（`D-049`）を特徴量として持つことで行う
- **同日レースの参照は `F-501` `F-502` に限る（`D-010`）。** 判定は `(date, course, race_number)` の厳密不等号
- **対象レースの実測ラップ・走破タイム・着順を入力にしない（`D-007` / 原則5）**
- **集計統計量の推定期間も `as_of` で切る（`R-019` / 原則7）。** `μ_global` を全期間で計算しない
- **`F-901` をレース単位の変数に適用しない（`D-021`）**
- 回収率は信頼区間なしに報告しない（`D-008`）。本仕様は回収率を扱わない
