# ドメインレビュー

UMAGICの設計・実装が、競馬の実態と合っているかを見る。

## このスキルが要る理由

設計と競馬の実態のズレは、**コードとしては正常に動く**。だから単体テストにもリーク検査にも引っかからず、「なぜか精度が出ない」という形で最後まで残る。

実際にこのプロジェクトで見つかった例を挙げる。いずれも書いた時点では気づかれず、ドメイン側から見て初めて分かった。

| 欠陥 | 見つからなかった理由 |
|---|---|
| `races` に発走順序の列がない | スキーマとしては整合していた。同日複数場開催という**運営の実態**を知らないと気づけない |
| `corners` の要素数が距離で変わる | 配列として扱えば動く。**短距離にはコーナーが2つしかない**という事実が抜けていた |
| 外国馬に過去走が1行もない | 欠損として処理はできる。**G1にだけ外国馬が来る**という対象固有の事情 |
| 取消と競走中止で返還が違う | どちらも「走らなかった馬」に見える。**払戻規則**の話 |

共通するのは、**プログラムとして正しいが競馬として間違っている**という形をしていること。

## 最大の危険：もっともらしい競馬談義

このスキルが最も壊れやすいのは、**検証されていない相場観を断定口調で出す**方向である。「叩き2走目は走る」「この血統は道悪が得意」「内枠有利」。どれも聞いたことがあるが、どれもこのプロジェクトで検証されていない。

断定すると害が出る。読んだ人が事実として扱い、`D-xxx` の根拠に使われ、検証されないまま設計に埋まる。**未検証の民間伝承を設計の基礎にするのは、何も指摘しないより悪い。**

だから指摘には必ず確度を付ける。

### 確度の3段階

**① 構造的事実** — レース運営・データの成り立ち・規則から必然的に決まること。**断定してよい。**

- 短距離戦にはコーナーが2つしかない（距離とコース形態で決まる）
- 外国馬・地方馬にはJRAの過去走が存在しない
- G1は定量・馬齢重量が中心で、斤量の分散が小さい
- 同日に複数の競馬場で開催がある
- 出走取消・除外は返還あり、競走中止・失格は返還なし
- 実測ラップ・走破タイム・着順は発走後にしか確定しない
- 馬体重は当日発表、最終追い切りは開催週の水曜前後

**② 傾向** — 多くの予想家が同意するが、このプロジェクトのデータで検証していないこと。**仮説として出し、検証方法を必ず添える。**

- 前哨戦を叩いた馬と直行の馬で成績が違う
- 激走の次走は反動が出る（`F-601` が既にこの形で登録されている）
- 種牡馬ごとに馬場適性の差がある

`domain-knowledge.md` の `F-601` が「真偽はデータが答える。`P-3` で仮説として投入し、効かなければ捨てる」と書いてあるのが、この扱いの手本になる。

**③ 未検証の推測** — 自分の一般知識から出たが、`docs/` にも根拠がないこと。**そう明示する。**

### 数値は特に危険

「1番人気の勝率は約32%」「複勝の的中率は6割」といった**具体的な数値を記憶から断定しない**。近い値であっても、根拠なく書かれた数値は後で検証されずに引用される。

数値を出す必要があるときは、`docs/` に記録済みのもの（控除率、G1のレース数、標準誤差の計算）を参照するか、「要検証」と明示して確認方法を添える。

## 手順

### 1. 記録済みの知識を先に読む

**自分の一般知識ではなく、プロジェクトに記録された知識を基準にする。**

- `docs/domain-knowledge.md` … 特徴量カタログ（`F-xxx`）、プロの予想プロセス、G1固有の性質、リーク防止の原則
- `CLAUDE.md` の「設計原則」 … 直感に反する決定の一覧
- `docs/decisions.md` … 確定済みの判断（`D-xxx`）

読まずに指摘すると、**既に検討済みのことを蒸し返す**。`CLAUDE.md` には「G1では一般的な競馬予想の知見が反転する」と明記されており、一般論をそのまま当てると外す。

### 2. 対象を読む

依頼された範囲（仕様書・特徴量・スキーマ・実装コード・会話中のアイデア）を読む。

### 3. 観点で走査する

以下は熟練の予想師が実際に引っかかる箇所を、機械的に確認できる形に落としたもの。**上の2つが最も収穫が多い**（過去に見つかった欠陥の大半がここに当たる）。

**① 条件によって定義が壊れないか** ← 収穫が多い

同じ処理が全レースで同じ意味を持つとは限らない。

- 距離でコーナー数が変わる（短距離は2角まで、新潟直線1000mはコーナーなし）
- 芝とダートで意味が変わる特徴量はないか
- 少頭数と多頭数で解釈が変わらないか（8頭立ての「4番手」と18頭立ての「4番手」）
- 障害戦、新馬戦、地方交流で前提が崩れないか
- 同着、失格、降着、競走中止の扱い

**② 全馬について計算できるか** ← 収穫が多い

- 外国馬、地方馬、初出走、長期休養明け、転厩直後
- 計算できない馬がいるとき、レース内相対化（`F-901`）の母数と平均が歪まないか
- 「データがないから低評価」になっていないか（強い馬を機械的に切る形になる）

**③ 発走時点で本当に分かるか**

リーク検査（`004-leakage-test.md`）とは別の角度で見る。時刻の粒度で見落とす。

- 馬体重は当日発表、最終追い切りは開催週、枠順は木・金
- オッズはいつ時点のものか（`D-002` の線引きに触れていないか）
- 「同日の前のレース」の前後判定が正しいか（`D-010`）

**④ G1で反転していないか**

条件戦・ハンデ戦の常識を持ち込んでいないか。`domain-knowledge.md` 3節に一覧がある。

- 斤量（G1は定量中心で情報量が低い）
- 前走着順（前哨戦は叩き台）
- クラス実績の絶対値（全頭が実績馬）

**⑤ 市場が既に織り込んでいないか**

`D-002` の目標は市場確率を超えること。人気・実績・血統といった**分かりやすい情報**は既にオッズに入っており、それを特徴量にしても原理的に超えられない。`domain-knowledge.md` 2節の優先度表と照らす。

**⑥ 交絡していないか**

- 騎手の成績は馬質と交絡する（上位騎手は良い馬に乗る）
- 厩舎、馬主、種牡馬も同様
- 交絡除去の方法が `D-002` の線引きを越えていないか（`Q-006`）

**⑦ サンプル数が足りるか**

- 少産駒の種牡馬、新人騎手、特殊条件のコース
- 縮約（`F-902`）が適用されているか

**⑧ 時代で変わらないか**

- ローテーション文化、馬場改修、ルール改定、種牡馬構成
- `D-018` の年代別報告で見えるようになっているか

**⑨ 例外開催で壊れないか**

- 降雪等による順延・代替開催（曜日が動く）
- 開催の振替、コース変更（芝→ダート）

### 4. 確度を分けて重要度順に出す

各指摘に確度を付ける。**構造的事実でないものを構造的事実として書かない。**

重要度は「設計の柱が崩れるか」で決める。`D-007`（2段階構成）や `D-002`（市場超え）に触れるものが最上位で、特徴量1つの精度に関わるものは下。

## 出力の形

```markdown
## 指摘 1: <一文で要点>

**確度**: 構造的事実
**対象**: `docs/domain-knowledge.md` F-101 / `src/umagic/features/pace.py:42`
**何が起きるか**: 短距離戦ではコーナー通過順が3角・4角しか記録されないため、
  1〜2角を要求する F-101 が算出できない。3・4角で代用すると「意欲」ではなく
  「結果」を読むことになり、特徴量の意味が反転する。
**対応案**: 要素数が足りないレースは入力なしとして扱う。`Q-xxx` として起票するか、
  `F-101` の定義に条件を追記する。
```

傾向・未検証の場合は **確認方法** を必ず足す。

```markdown
**確度**: 傾向（このプロジェクトでは未検証）
**確認方法**: 前走からの間隔で層別し、G1での複勝率を比較する。
  `D-018` の年代別集計と合わせないと、ローテ文化の変化と混同する。
```

## 指摘が無ければ「無い」と言う

**指摘のために指摘を作らない。** 毎回それらしい問題を10件出すレビューは、本物の問題が混ざったときに埋もれさせる。

見るべき観点を通したうえで問題が無ければ、「以下の観点で見て、ドメイン上の食い違いは見つからなかった」と観点を挙げて報告する。それ自体が価値のある結果になる。

気になるが確信が持てないものは、指摘ではなく **「確認したほうがよい点」** として分けて出す。

## このスキルの範囲外

- **修正を適用すること。** 指摘までが仕事。直すかどうか、どう直すかはユーザーが決める。`docs/` を書き換えるなら `spec-hearing` に渡す。
- **`docs/` に記録すること。** 採用された指摘を `Q-xxx` や `F-xxx` にするのは、ユーザーが判断してから。
- **予想そのもの。** 個別レースの予想を出すスキルではない。
